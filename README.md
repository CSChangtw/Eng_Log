# B14-4 建築物施工日誌（個人版）V2.2.1

用手機離線填寫施工日誌，存進自己的 Google 雲端硬碟。程式是 PWA 靜態網頁，可以部署在公司或個人的 GitHub Pages。

- **表單依據**：110 年版「建築物施工日誌 B14-4」，含後附的「建築物施工日誌之技術士簽章表」。欄位名稱、項次和註 1～5 都照原表單文字。
- **資料存放**：日誌先存在手機瀏覽器（IndexedDB），按「同步」後存到使用者**個人** Google 雲端硬碟。本系統沒有後端伺服器，不經手、不保存任何日誌資料。
- **雲端權限**：只申請 `drive.file`，也就是只能存取本系統自己建立的檔案，看不到使用者雲端硬碟裡的其他檔案。

## 分頁設計（V2.2.0）

| 分頁 | 內容 |
|---|---|
| 清單資料 | 新增日誌、同步、本機日誌清單（依工程篩選、關鍵字搜尋）、雲端日誌還原；表頭（日期、星期、表報編號、天氣）與工程基本資料 |
| 施工材料 | 一、施工項目，以及營造業專業工程特定施工項目 A／B；二、工地材料管理 |
| 人員機具 | 三、人員與機具；四、技術士設置（勾「有」才顯示技術士簽章表） |
| 職安其他 | 五、職安施工前檢查與其他事項；六、取樣試驗；七、通知協力廠商；八、重要事項（含註 4 範本） |
| 附件簽章 | 照片／附件、簽章人與核對勾選，以及全部分頁的「填報檢查」彙總 |
| 設定 | 匯出／匯入、刪除、Google OAuth 用戶端 ID、儲存空間狀態 |

- 六個分頁在手機直向畫面可一次顯示，不必左右捲動。目前開啟的日誌（日期、工程、同步狀態、是否編輯中）固定顯示在分頁列下方。
- 有缺漏的分頁會在標籤右上角出現**橘點**。在「附件簽章」頁點選填報檢查項目，會跳到對應分頁並捲到該區段，例如點選天氣缺漏會跳到「清單資料」的表頭。
- 從清單開啟日誌或新增日誌後，畫面會自動捲到表頭。
- 每頁底部有「上一頁／下一頁」按鈕，手機上也可以在空白處左右滑動切換。
- 「帶入前一日項目與累計」按鈕放在一、二、三區段頂端（按任一個都會一次帶入一～三項）。
- 支援網址錨點：`#list`、`#work`、`#labor`、`#safety`、`#sign`、`#settings`。舊版錨點（例如 `#material`）會自動對應到新分頁。

## 主要功能

| 功能 | 說明 |
|---|---|
| 表單欄位 | 表頭、工程基本資料、一～八項、簽章欄，全部依 110 年版 B14-4。第四項勾「有」時，才會出現並列印技術士簽章表（A～F） |
| 累計自動計算 | 每列有「前日累計」欄位，填入本日數量後，累計 = 前日累計 ＋ 本日，算出後仍可手動修改 |
| 帶入前一日資料 | 新增日誌時可以沿用同一工程，自動帶入前一日的項目、單位、契約數量和累計數量 |
| 自動儲存 | 停止輸入 1.5 秒後自動存到本機；切換 App 或關閉頁面時也會先存檔 |
| 預覽／列印 | 照 B14-4 版面產生 A4 頁面，可以直接列印或另存 PDF；預覽時會順便列出欄位缺漏提醒 |
| 照片壓縮 | 照片長邊縮到 2000px、JPEG 品質 0.85，減少行動數據用量（可以關掉） |
| 雲端同步 | 存放路徑是 `個人施工日誌／工程名稱／年／月`，日誌存成 JSON，附件另存成獨立檔案 |
| 衝突保護 | 雲端版本被其他裝置改過時，系統只標示「衝突」，不會自動覆寫；由使用者選擇保留本機版本或改用雲端版本 |
| 雲端還原 | 列出雲端上的日誌，選一筆即下載還原到目前裝置（附件一併下載） |
| 備份 | 可以匯出單筆或全部 JSON，也可以匯入 JSON |
| 刪除 | 刪除本機日誌時，可以選擇是否把雲端檔案一起移到垃圾桶 |

### V2.0.2 修正項目（相對 V2.0.1）

| # | V2.0.1 缺失 | V2.0.2 修正 |
|---|---|---|
| 1 | 日期取自 UTC，台灣時間 00:00～07:59 新增日誌會變成前一天 | 一律使用裝置本地日期，並自動顯示星期 |
| 2 | 判斷衝突時，拿手機時間跟 Google 伺服器時間比較，手機時鐘不準就會誤判 | 改成兩邊都用伺服器時間比較：雲端目前的 `modifiedTime` 對照上次同步時記下的值 |
| 3 | 每次同步都重新上傳全部附件；從雲端還原的附件會先下載再上傳一次 | 只上傳新增或修改過的附件；每個附件傳完就立刻寫回本機，中途斷線也不會重複建立檔案 |
| 4 | manifest 沒有圖示，Chrome 不會出現安裝提示 | 補上 192／512／maskable 圖示 |
| 5 | 沒有要求瀏覽器持久保存資料 | 呼叫 `navigator.storage.persist()`，並在設定區顯示目前保存狀態與已用空間 |
| 6 | 修改工程名稱或日期後再同步，雲端檔案還留在舊資料夾 | 同步時一併把日誌和附件移到正確的資料夾 |
| 7 | 沒網路時，對 Google API 的請求會被誤回成 index.html | Service Worker 不再攔截跨來源請求；頁面改成先連網路、超過 4 秒才用快取，並在有新版時提示更新 |
| 8 | 授權 token 過期後，同步直接失敗 | 記錄 token 到期時間，快到期時於按下按鈕時自動重新授權；收到 401 時提示再按一次 |
| 9 | 欄位與 110 年版不一致（缺技術士簽章表表頭、特定施工項目只有文字欄等） | 依 110 年版重新整理：加入建（雜）照號碼、專業工程項目、應置技術士人數、特定施工項目 A/B 列、簽章人身分 |
| 10 | 不能刪除、篩選、匯入，也不能列印 | 新增工程篩選、關鍵字搜尋、匯入、刪除，以及預覽／列印 |

## 使用限制

- **仍屬開發原型**：還沒完成正式資安稽核與多機型壓力測試。正式報備前，請確認案件所屬主管建築機關目前使用的表單版本；依註 2，主管建築機關可以自行增訂欄位。
- **系統不代簽**：不產生電子簽章。列印後由工地主任（或營造業法第三十二條第二項所定之人員）以及技術士本人簽章。
- **授權約 1 小時有效**：Google 授權 token 只存在記憶體裡。過期或重新整理頁面後，下次按同步會再跳出授權視窗。沒有後端，所以不做背景自動同步。
- **衝突只比對整筆**：只判斷整筆日誌是否被改過，不做逐欄位合併。
- **本機草稿未加密**：請開啟手機螢幕鎖，並定期同步、匯出備份。清除網站資料會刪掉還沒同步的日誌。
- **從 V2.0.1 升級**：既有日誌會沿用並自動轉換格式。V2.0.1 從雲端還原過的日誌，第一次同步時可能會顯示一次「衝突」，選「以本機版本覆寫雲端」或「改用雲端版本」即可。

## 本機測試

```bash
python3 -m http.server 8080
# 電腦瀏覽 http://localhost:8080
```

Service Worker 和 Google 授權都需要 HTTPS，`localhost` 是例外。手機實測請先部署到 GitHub Pages，步驟見 `DEPLOY.md`。
